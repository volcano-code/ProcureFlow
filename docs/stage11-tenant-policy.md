# 阶段十一：租户采购政策版本与审批绑定

## 业务范围

每个工作区维护自己的不可变采购政策版本。授权审批人可发布下一版本，采购人与审计人可读取当前版本及完整历史。政策管理不会授予采购人审批权，也不会让只读 Agent 获得写入工具。

- `budget_cap`：可空的 CNY 总价上限。非空时与需求预算取更严格值
- `max_delivery_days`：可空的最大交货天数。非空时与需求交期取更严格值；这是相对交期上限，不是绝对日历日期或工作日模型
- `minimum_valid_quotes`：1–100 家不同供应商的合格报价。只计已确认、币种/物料/数量/单位一致、费用明确且满足需求和政策上限的报价；同一供应商多个报价不重复计数。供应商标识符保持大小写敏感
- 首个租户政策没有额外预算/交期上限，最低有效报价数为 1，以保持已有本地演示兼容。需求自身的限制仍生效；这不是替任何企业制定采购制度

政策不能放宽单 SKU/CNY/EA、明确税费/运费/折扣、独立审批、只创建 ERP 草稿、不支付与不盲目重放等固定安全约束。政策不是任意脚本、外部制度文档检索或模型生成的授权。

## 发布时间与并发

每个版本记录发布人、发布时间、生效时间、变更原因和内容哈希。发布请求必须提供最新已发布版本号作为乐观锁，包括尚未生效的版本。并发更新只有一个可成功；另一方必须刷新再决定，不能静默覆盖。

`effective_at=null` 表示现在生效；未来时间必须有时区，服务端规范化为 UTC。拒绝回溯生效时间。当前政策始终取已经生效的最高版本号，因此旧的预约版本到点后不会把已生效的新版本回退。取消预约/回退政策需要发布一个新的版本，不能编辑、删除或重用历史版本号。

未来版本的发布本身不使当前审批失效；其实际生效会在读取和授权关口重新计算，无需定时任务。生效检查以服务端时钟为准，部署需保证时钟同步。跨系统没有分布式事务；已经提交 ERP 的历史草稿不会因后续政策变化被自动删除。

## 精确绑定与历史

确定性比较、审批快照和只读建议绑定当时的完整需求、有效政策内容/版本/哈希以及全部报价版本与证据摘要。非中选报价的变化也会让旧结果失效，不能只重验中选供应商。

每次分析保留一个不可变评估记录，包括阻止推荐的原因、有效供应商数、完整输入和当时的报价/推荐输出。历史读取区分当时的事实和是否仍适用于当前状态；政策、报价或需求改变后不能把旧结果当作当前授权。建议保存所用输入，旧运行不会因重复请求自动重新调用模型。

审批、执行预留及 Worker 最终外部写入前都重新校验。租户政策锁先于需求锁，发布和业务关口使用同一锁顺序；最终检查与草稿创建处于同一个锁保护窗口，阻止政策发布插入检查与写入之间。未来政策到点由最终关口检查，而非靠发布时的批量失效操作。授权线性化点是最终检查：外部请求飞行期间时钟可能跨过生效时间，不能将本地锁解释为跨 ERP 的原子时间事务。

租户锁是保守的安全边界：同一租户的业务写入会串行，较慢的 ERP 调用可能阻塞该租户其他更新并触发既有锁等待超时。本阶段未声称高并发吞吐量，也未实现跨系统事务。

完成或结果不确定的 ERP 操作保留原始绑定；恢复只读核对原操作，不能利用新政策重放一次外部写入。旧版数据库已有审批若缺少新的政策/全集合绑定，必须重新分析审批；历史原始记录不应被伪造为已采用新政策。

## API

- `GET /api/v1/policy`：当前有效政策、最新已发布版本号
- `GET /api/v1/policy/versions`：按版本降序的历史；状态为 effective / scheduled / superseded
- `POST /api/v1/policy/versions`：审批人发布；`expected_version` 针对最新已发布版本，附限制、`effective_at` 和 `reason`
- `GET /api/v1/requests/{id}/evaluations`：隔离工作区的历史评估及当前有效性
- `GET /api/v1/requests/{id}/approvals`：历史审批、当时快照与当前有效性
- 需求增加 `proposal_current` / `proposal_stale_reason`；持久化建议增加当时输入绑定

评估和审批历史支持 `offset`（默认 0）及 `limit`（默认 100，最大 200）分页，历史不会因超出首屏而不可读取。旧版建议缺少保存输入时返回 `LEGACY_INPUT_UNBOUND`，保留原始回执且不重放。

版本冲突返回 `VERSION_CONFLICT`，回溯日期返回 `POLICY_BACKDATE_DENIED`。所有历史读取仍受租户隔离；猜测其他工作区 ID 不会获得其政策、评估或报价。

原生工作台提供当前政策、预约/历史版本、发布原因、精确输入绑定、违规原因和过期提示。界面提示不是授权机制，服务端仍会独立阻止过期执行。

## 迁移与验收

当前新增迁移头为 `a82d71f09c36`，上一版本为 `5ce3ab9b84a2`。更新前停止应用/Worker，备份数据库，并先在副本执行 Alembic upgrade head 与回归。生产实例不得通过 SQLite `create_all` 替代迁移。降级会丢失新增政策/评估历史，不应无备份执行。

验收必须区分 SQLite 本地核心测试、PostgreSQL 并发测试、Next 类型/构建检查、真实浏览器，以及真实 ERP 沙箱。PostgreSQL 严格入口包含政策版本和对抗用例；缺少服务不降级到 SQLite 冒充通过。既有远端 CI 成功不代表此增量也通过。

此阶段未增加 OCR/复杂文档导入，未选择真实模型提供方、型号或费用预算，未做付费调用。十个冻结合成 development 任务仍是离线回归，不是新增真实模型质量结论。
