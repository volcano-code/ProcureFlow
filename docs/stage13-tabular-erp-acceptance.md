# 阶段十三：普通 CSV/XLSX 到隔离 ERP 的验收合同

本增量扩展验收入口，不增加生产采购权限。测试脚本存在、离线回归通过，均不代表该提交已完成真实 ERPNext 验收；真实结论必须绑定确切提交及 SQLite/PostgreSQL 两条隔离 CI 的原始记录。

## 八条外部草稿路径

保留既有四条 TXT 成本回归（含税正常、含税丢回执、未税折扣、含税折扣），另增加四条普通表格路径：

- CSV 未税折扣：商品 2,000.00 − 折扣 100.00 + 商品税 247.00 + 最终含税运费 80.00 = CNY 2,227.00
- CSV 含税折扣并丢回执：商品含税 2,260.00 − 商品折扣 113.00 + 运费 80.00 = CNY 2,227.00
- XLSX 未税折扣：同上未税成本合同
- XLSX 含税折扣并丢回执：同上含税成本合同

真实沙箱只允许 8 次 Supplier Quotation POST、8 个不同草稿，全部 docstatus=0，Purchase Order 和已提交报价都必须为零。独立数据库检查仍核对逐项金额、原税额/折后税额、净额、运费、折扣、账户、哈希、唯一约束及权限。不能仅凭总价相等通过。

## 表格输入与生产 HTTP 流程

`scripts/erp_tabular_fixtures.py` 生成可重现的真实 CSV/OOXML XLSX 文件字节。供应商 ID 取一次性沙箱创建的合成供应商，不假设 ERP 命名规则。文件有中文重排表头、封面行、其他 SKU 干扰行和重复报价行；XLSX 另有封面工作表，CSV 干扰行含换行文本。

每条表格路径通过实际业务 HTTP API 完成：

1. 上传文件并检查 SHA-256；重复上传必须复用同一预览；此时没有报价
2. 未预览确认被拒绝；跨租户不可读取；选择其他 SKU 行被拒绝
3. 明确选择 CSV 或第二张 XLSX 工作表“报价明细”、第 3 行表头、第 5 行报价和全部 11 字段列映射
4. 保存预览后重启 API，读回完全相同的映射/来源；旧 revision 不能导入
5. 显式导入一份未确认报价；分析仍不可提出方案；重复确认、API 重启后确认及重复上传均复用同一报价
6. 核对原文件哈希、文档 ID、所有字段的工作表/行/列/单元格/表头定位及实际片段文本。CSV 第 5 个逻辑报价行的实际文件行必须是第 6 行
7. 以 buyer 身份显式确认报价，再比较、由独立 approver 批准快照、入队、独立 Worker 创建 ERP 草稿
8. auditor 独立读回全部费用组件，跨租户拒绝读回，重复执行和导入回执重放均不得增加 POST

两条含税表格路径会在 ERP 提交草稿后由回环故障网关返回 504。先验证 RECONCILING，再重启 API，并由新的 Worker 进程只读找到原草稿；整条操作仍只能有一次 POST。最后再次重启 API 核对八个远端 ID。

## 陈旧批准与失败关闭

额外 CSV/XLSX 需求仅用于拒绝测试，不创建外部操作：导入、确认并批准后修改运费，旧批准必须拒绝；重新确认并批准后发布新的租户政策版本，旧政策快照也必须拒绝。原有未批准、自批和陈旧需求拒绝测试保留。

CI 保留四份原始合成表格文件到 input-fixtures；证据检查器重新计算文件 SHA-256，与每条来源回执绑定，缺失或篡改文件也必须失败。

证据检查器要求精确八场景顺序、格式、步骤、数量、真实布尔值以及四套完整来源对象；缺失来源、列/行漂移、哈希不一致、重复导入/报价 ID 或旧四草稿报告均失败。旧历史记录并未被修改，它们只不满足新增合同。

## 运行与界限

- 离线回归：`python scripts/test.py -q tests/test_erp_tabular_acceptance.py tests/test_erp_evidence_gate.py tests/test_erp_acceptance_audit.py tests/test_erp_permission_probes.py`
- 完整隔离 ERP：沿用 `.github/workflows/erp-sandbox.yml` 的 seed → HTTP/Worker → 负向 REST 权限 → 独立 ERP 数据库审计 → 证据门槛流程；SQLite 和 PostgreSQL 分别运行，不互相替代
- 本地全链路 harness 回归启动真实 API、解析器子进程、Worker 和重启流程，但 ERP 上游是明确的 HTTP 测试替身，不能作为真实 ERP 或税务引擎结果

本轮真实 ERP 路径通过 HTTP 驱动，不是原生浏览器到真实 ERP 的联合测试；原生表格 UI 仍由独立 MockERP 浏览器门槛覆盖。保持单 SKU、CNY、EA，不支持多物料合并、OCR、任意税务/单位换算。审批身份为自动化模拟人工角色，不是人工采购研究；不使用生产凭据或付费模型。
