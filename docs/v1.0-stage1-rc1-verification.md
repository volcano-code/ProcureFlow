## 3. PostgreSQL duplicate-key 日志已定位为预期约束测试

RC head 的 `services/api/tests/test_postgres.py` 中，`test_postgres_uniqueness_is_enforced_by_database` 明确执行两次受控冲突：

- 对同一 request 插入第二条 `OperationRow`，断言抛出 `IntegrityError`，对应唯一约束 `uq_one_operation_per_request`。
- 对同一 operation 插入第二条 `OutboxRow`，断言抛出 `IntegrityError`，对应唯一约束 `outbox_operation_id_key`。

因此 PostgreSQL 服务日志中的这两条 duplicate-key ERROR 是该测试主动验证数据库唯一约束时预期产生的服务端日志，不是本轮 PostgreSQL JUnit 失败。该测试在 RC head 的 PostgreSQL 集成门槛中运行成功。不能仅因日志级别为 ERROR 就把它归类为产品故障；也不能把这两条日志解释为运行时并发错误。
